# 벌티 펀드 주문

벌티(버라이어티 쇼) 펀드 음식 주문을 받는 웹앱이다. 2025년 앱에서 주문 기능만 떼어 새로 만들었다.

화면은 세 개로 완전히 나뉘어 있고 서로 링크도 걸려 있지 않다.

| 화면 | 주소 | 쓰는 사람 |
|---|---|---|
| 학생 주문 | `index.html` | 주문하는 학생, 선생님 |
| 펀드 | `fund.html` | 펀드 담당자 (role이 `fund`인 계정) |
| 개발자 | `dev.html` | `DEVELOPER_EMAILS`에 등록된 계정만 |

데모 주소: https://kanghyeon0220.github.io/fund-demo/ (펀드는 `fund.html`, 개발자는 `dev.html`을 뒤에 붙인다)

빌드 과정이 없는 HTML/JS라서 파일을 그대로 올리면 된다. 휴대폰에서 학생 화면을 열고 "홈 화면에 추가"를 누르면 앱처럼 쓸 수 있다.

## 바로 써 보기 (데모 모드)

`js/config.js`의 `firebaseConfig`가 `null`이면 데모 모드로 돈다. 주문과 메뉴가 그 브라우저 안에만 저장된다.

1. https://kanghyeon0220.github.io/fund-demo/ 를 연다. GitHub Pages는 `gh-pages` 브랜치에서 나간다. 코드를 고치면 `main`과 `gh-pages` 둘 다에 올려야 사이트에 반영된다 (`git push origin main main:gh-pages`).
2. 메뉴를 고르고 주문한다.
3. 같은 브라우저 다른 탭에서 `fund.html`을 열고 "데모 펀드 담당자로 들어가기"를 누른다. 방금 한 주문이 보인다.
4. 펀드 탭에서 상태를 바꾸면 주문 탭에 알림이 뜬다.
5. `dev.html`에서 "데모 개발자로 들어가기"를 누르면 지금까지의 로그인 기록이 보인다.

컴퓨터에서 직접 열 때는 `index.html`을 더블클릭하면 안 되고(모듈이 막힌다) 폴더에서 `python -m http.server`를 실행한 뒤 `http://localhost:8000`으로 연다.

## 실제로 쓰기 (Firebase 연결)

1. https://console.firebase.google.com 에서 새 프로젝트를 만든다.
2. Authentication > 로그인 방법에서 Google과 이메일/비밀번호를 켠다.
3. Firestore Database를 만든다 (위치는 asia-northeast3 서울).
4. 프로젝트 설정 > 내 앱 > 웹 앱 추가. 나오는 설정값을 `js/config.js`의 `firebaseConfig`에 붙여 넣는다.
5. `firestore.rules` 내용을 Firestore > 규칙 탭에 붙여 넣고 게시한다. 이걸 빼먹으면 아무나 남의 주문을 볼 수 있다.
6. GitHub Pages로 올렸다면 Authentication > 설정 > 승인된 도메인에 `아이디.github.io`를 추가한다. 안 하면 구글 로그인이 막힌다.
7. 개발자 계정 정하기: `js/config.js`의 `DEVELOPER_EMAILS`와 `firestore.rules` 맨 위 `developerEmails()`에 내 구글 이메일을 똑같이 넣는다 (규칙 쪽은 소문자로). 그 계정으로 `dev.html`에 구글 로그인하면 된다. 이메일/비밀번호 계정은 이메일 인증이 안 돼 있어서 규칙에서 개발자로 인정되지 않는다. 개발자는 구글 로그인으로 들어간다.
8. `js/config.js`의 `SHOP`에 계좌 정보, 문의처, 인스타그램 주소를 넣는다. `bankInfo`가 비어 있으면 계좌이체 선택지가 안 보인다.

Firebase Hosting을 쓰고 싶으면 `npm i -g firebase-tools` 후 `firebase login`, `firebase use --add`, `firebase deploy`를 하면 된다. `firebase.json`이 이미 있어서 규칙과 사이트가 같이 올라간다.

## 권한

| 권한 | 할 수 있는 일 |
|---|---|
| 일반 | 주문, 내 주문 보기, 접수됨 상태일 때 취소 |
| 펀드 담당 (`fund`) | 모든 주문 보기, 상태 변경, 입금 확인, 메뉴·품절, 주문 받기 켜고 끄기, 공지 |
| 개발자 | 전부. 로그인 기록 보기·삭제, 펀드 권한 주고 빼기, 주문 상태 강제 변경, 주문 삭제, 전체 백업 |

개발자 권한은 users 문서의 role이 아니라 이메일로 정해진다. 규칙에 이메일이 박혀 있어서 다른 사람이 role을 바꾸거나 지워도 개발자 권한은 빠지지 않는다. 개발자 화면에서는 개발자 계정의 권한 칸이 "개발자 (고정)"으로 나오고 바꿀 수 없다.

주문 상태는 접수됨 > 만드는 중 > 배달 중 또는 픽업 대기 > 완료 순서로 간다. 취소도 있다.

## 메일 인증과 비밀번호

- 회원가입할 때 형식이 틀린 메일(@ 없음, 점 없음 등)은 막는다. 학생 화면과 store 양쪽에서 확인한다.
- 가입하면 Firebase가 인증 메일을 보낸다. 인증 전에는 학생 화면 위에 "메일 인증이 아직 안 됐어요" 배너가 뜨고, 거기서 메일을 다시 보내거나 인증 여부를 새로고침할 수 있다. 개발자 화면의 사용자 표에 인증됨/미인증이 나온다.
  - 인증 메일이 스팸함으로 가면 Firebase 콘솔 Authentication > Templates에서 보내는 주소를 확인하거나, 커스텀 도메인을 붙이면 도착률이 올라간다.
  - 데모 모드는 실제 메일을 못 보내서, 배너의 "데모: 인증 완료 처리" 버튼이 인증을 대신한다.
- 비밀번호는 Firebase가 복원 불가능한 값으로만 저장해서 누구도 원본을 볼 수 없다. 이건 바꿀 수 없고, 바꿔서도 안 된다. 비밀번호를 잊은 학생은 개발자 화면 사용자 표의 "재설정 메일" 버튼으로 재설정 링크를 보내면 본인이 새로 정한다.

## 현장 주문 기록

펀드 화면과 개발자 화면에 "현장 주문" 탭이 있다. 부스 앞에서 바로 받은 주문을 담당자가 적는 곳이다.

엑셀 같은 표에 줄마다 하나씩 적는다. 열은 이름 학년반, 물품, 수량, 가격, 결제, 요일이다.

- 물품을 고르고 수량을 바꾸면 가격이 자동으로 채워진다. 가격은 손으로 고칠 수도 있다.
- 결제는 현금, 계좌, 외상 세 가지다. 외상은 나중에 받을 돈이고, 회계와 매출에 "외상 받을 돈"으로 따로 합계가 나온다.
- "기록하기"를 누르면 다 채운 줄이 온라인 주문과 같은 곳(orders)에 저장돼서 주문판, 회계 정리, 매출에 똑같이 들어간다. 저장된 줄은 "기록됨"으로 잠기고, 빈 줄이 새로 깔린다. 위치는 "현장"으로 적히고 "현장" 태그가 붙는다.
- "줄 추가"로 줄을 더 넣는다.

구매자가 주문할 때 고른 결제방식은 주문 확인 화면과 "내 주문" 카드(현금/계좌이체 태그), 펀드 담당자 주문 카드에 모두 표시된다.

## 회계 정리

펀드 화면과 개발자 화면에 "회계 정리" 탭이 있다. 주문을 결제방법별로 묶어서 보여준다.

- 한 줄이 주문 하나다. 번호, 반 이름, 주문 내용(메뉴 × 수량), 수량 합계, 총 가격, 결제방법.
- 결제방법(현금, 계좌이체)별로 묶여서 각 소계가 나오고, 맨 위에 취소 뺀 전체 합계가 나온다.
- 위쪽 버튼으로 현금만, 계좌이체만 걸러 볼 수 있다. "취소 주문 포함"을 켜면 취소된 주문도 줄 그어진 상태로 같이 보인다 (합계에는 안 들어간다).
- "회계 CSV 받기"로 엑셀로 받을 수 있다.

## 로그인 기록

누가 언제 들어왔는지 `login_logs` 컬렉션에 남는다. 개발자 화면 첫 탭에서 본다.

- 남는 것: 시간, 이메일, 이름, 종류(로그인, 회원가입, 재방문, 로그아웃), 방법(구글, 이메일), 어느 화면에서 들어왔는지, 기기(예: iOS · Safari), 브라우저 정보 원문
- 재방문은 이미 로그인된 채로 사이트를 다시 연 경우다. 탭을 새로 열 때마다 한 번 남는다.
- 이메일로 걸러 보기, 종류·화면별로 걸러 보기, CSV 받기, 전체 삭제가 된다.
- 사용자·권한 탭에는 사람마다 마지막 로그인 시간과 로그인 횟수가 나온다.
- 규칙상 본인 기록만 쓸 수 있어서 남의 이메일로 가짜 기록을 만들 수 없다. 기록은 개발자만 읽고 지울 수 있고, 고치는 건 아무도 못 한다.
- 로그인에 실패한 시도(비밀번호 틀림 등)는 남지 않는다. 로그인 전이라 누구인지 확인할 수 없어서, 이걸 받으면 아무나 기록을 채워 넣을 수 있게 된다.
- 로그인 창마다 "로그인하면 이메일과 접속 시간이 기록돼요"라는 안내가 있다. 학생 개인정보를 모으는 거라서 이 안내는 지우지 않는 게 좋다. IP 주소는 브라우저에서 알 수 없어서 남지 않는다.

## 2025년 앱에서 바꾼 점

- 권한 확인을 화면 코드에만 두지 않고 `firestore.rules`에서 서버가 막는다. 작년에는 규칙이 느슨하면 누구든 자기 role을 developer로 바꿀 수 있는 구조였다.
- 사용자는 자기 role을 못 바꾼다. 개발자만 남의 role을 바꿀 수 있다.
- 내 주문을 이메일이 아니라 uid로 찾는다. 이메일 없는 계정도 주문 내역이 보인다.
- 주문마다 #1, #2 같은 번호가 붙는다. 픽업할 때 번호로 부르면 된다.
- 계좌이체 주문에 입금 확인 버튼이 있고, 매출 탭에 입금 안 된 금액이 따로 나온다.
- 현금 주문에 낸 금액을 적으면 관리자 화면에 거스름돈이 계산돼서 나온다.
- 주문 받기 스위치와 공지 칸이 생겼다.
- 매출 탭에서 메뉴별 판매량을 보고, 전체 주문을 CSV(엑셀)로 받을 수 있다.

## 알림에 대해

작년 웹 버전은 FCM 웹 푸시 키 자리에 `YOUR_PUBLIC_VAPID_KEY`가 그대로 들어가 있어서 웹 알림이 안 갔다. 이번 버전은 FCM을 쓰지 않는다. 페이지가 열려 있으면 Firestore 실시간 연결로 상태 변화를 바로 받아서 화면 알림과 브라우저 알림을 띄운다. 관리자 화면은 새 주문이 들어오면 소리가 난다.

화면을 완전히 닫은 상태에서도 휴대폰 푸시를 받게 하려면 Cloud Functions(유료 Blaze 요금제 필요)와 FCM을 붙여야 한다. 필요해지면 그때 추가한다.

## 파일

```
index.html               학생 주문 화면
fund.html                펀드 담당자 화면
dev.html                 개발자 화면
js/config.js             행사 정보와 Firebase 설정 (해마다 여기만 고치면 된다)
js/store.js              데이터 읽고 쓰기 (Firebase 모드 / 데모 모드)
js/app.js                학생 화면 동작
js/fund.js               펀드 화면 동작
js/dev.js                개발자 화면 동작 (로그인 기록, 권한)
js/panels.js             펀드·개발자 화면이 같이 쓰는 주문판, 메뉴, 매출
js/ui.js                 공통 함수 (상태 이름, 금액 표시, 알림)
css/style.css            디자인
firestore.rules          보안 규칙
manifest.json, sw.js     홈 화면 앱(PWA)
```

## 남은 일

- 주문 금액은 주문하는 쪽 화면에서 계산한다. 규칙이 금액이 메뉴 가격과 맞는지까지는 확인하지 않으니, 관리자가 주문을 받을 때 금액을 한 번 보면 된다. 확실히 막으려면 Cloud Functions로 서버에서 다시 계산해야 한다.
- 메뉴 사진은 주소(URL)로 넣는다. 사진 업로드가 필요하면 Firebase Storage를 붙인다.
